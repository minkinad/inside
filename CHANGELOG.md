# Changelog

All notable changes to Inside are documented here. The project follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and uses [Semantic Versioning](https://semver.org/spec/v2.0.0.html) when releases are published. No release tag exists yet.

## [Unreleased]

### Added

- Immutable 11-digit employee public IDs generated by a PostgreSQL sequence, with a backfill migration and isolated migration/concurrency tests.
- Repository validation, lint and format checks, CodeQL workflow, PR checks, Dependabot configuration and issue forms.
- Architecture, database, API, development, deployment and security documentation.

### Changed

- Rebranded the visible portal to min.Inside, added the supplied min symbol and a compact ecosystem menu, and moved light and dark accents to a violet and periwinkle token palette.
- Replaced the desktop sidebar and phone bottom bar with a responsive top navigation; rebuilt Home and employee profiles around the Inside visual system.
- Global search now includes brand materials and benefits alongside people and publications.
- Employee profile URLs and employee-facing API routes use `/people/employee/{number}`; API employee objects expose `publicId` rather than the internal database key.
- Demo seed now requires an empty database and never deletes existing records.
- Demo and existing local employee email addresses use `@min.ex`; company and content names use `min.Inside`. A data-only script and brand-asset replacement path preserve populated databases.
- Removed legacy color aliases and hard-coded diagram colors; accents, organization links and shadows now follow the shared violet tokens in both themes. Benefit filters also wrap on narrow screens.
- Administrative writes and audit entries commit together in a PostgreSQL transaction.

### Deprecated

- No deprecations in this unreleased change.

### Removed

- Internal employee IDs from employee-facing API responses.

### Fixed

- Protected web mutations reject foreign origins. Login rate limits use an atomic Redis operation and fail closed if Redis is unavailable.
- Successful profile-photo uploads update the UI without depending on an immediate profile refetch.
- The Next.js dependency tree uses a patched PostCSS release.

### Security

- Added response security headers, stricter production environment checks and safe download headers for brand assets.
- Brand upload removes the new object if its database transaction fails.
